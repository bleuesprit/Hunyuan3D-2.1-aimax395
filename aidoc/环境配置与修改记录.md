## 1. 原始环境问题分析

原始 `requirements.txt` 基于 CUDA + 较老 Python 版本设计，在当前 ROCm + Python 3.12 环境下存在以下冲突：

| 问题 | 原始要求 | 当前环境 | 影响 |
|------|----------|----------|------|
| numpy 版本 | `numpy==1.24.4` | `numpy 2.4.2` | 严重 API 不兼容 |
| Python 版本 | 隐含 ≤3.11 | Python 3.12.13 | numpy 1.24 等老包不支持 |
| GPU 平台 | CUDA (cupy-cuda12x) | ROCm 7.2 (AMD) | cupy-cuda12x 无法使用 |
| open3d 版本 | `open3d==0.18.0` | — | 无 Python 3.12 wheel |
| onnxruntime 版本 | `onnxruntime==1.16.3` | — | 不支持 Python 3.12 |
| tb-nightly | `tb_nightly==2.18.0a20240726` | — | PyPI 上找不到 |
| bpy | `bpy==4.0` | — | PyPI 无预编译 wheel |
| PyTorch 版本 | 未固定 | 2.9.1 (很新) | API 变化可能导致兼容问题 |

```python
model_fld = os.path.expanduser(os.path.join(base_dir, model_path))
model_path = os.path.expanduser(os.path.join(base_dir, model_path, subfolder))

# 修改后：先检查是否为绝对路径
if os.path.isabs(model_path) and os.path.exists(model_path):
    model_path = os.path.join(model_path, subfolder) if subfolder else model_path
    model_fld = os.path.dirname(model_path)
else:
    # ... 原有逻辑
```

**目的**: 允许直接传入本地模型目录的绝对路径，无需按 HF repo 结构组织。

### 3.3 `hy3dshape/hy3dshape/pipelines.py`

**方法**: `Hunyuan3DDiTFlowMatchingPipeline.to()`

**修改内容**: 修复 PyTorch 2.x 中 `to(dtype=str)` 的兼容性问题。

```python
# 修改前：直接传入字符串 dtype
self.vae.to(dtype=dtype)

# 修改后：字符串转 torch.dtype
if isinstance(dtype, str):
    dtype = getattr(torch, dtype)
self.vae.to(dtype=dtype)
```

**原因**: PyTorch 2.9 不再接受字符串形式的 dtype 参数，必须传入 `torch.dtype` 对象。

### 3.5 `hy3dpaint/DifferentiableRenderer/mesh_utils.py`

**修改内容**: `convert_obj_to_glb` 函数新增 trimesh fallback，支持无 bpy 环境运行。

1. `import bpy` 改为延迟导入，设置 `BPY_AVAILABLE` 标志
2. 原 bpy 实现重命名为 `_convert_obj_to_glb_bpy()`
3. 新增 `_convert_obj_to_glb_trimesh()` 用 trimesh + pymeshlab 实现同等功能
4. `convert_obj_to_glb()` 根据 `BPY_AVAILABLE` 自动选择实现方式

```python
# 修改前：直接 import bpy，没有 bpy 就整个模块崩
import bpy

def convert_obj_to_glb(...):
    # 全是 bpy 的逻辑
    bpy.ops.wm.obj_import(...)
    bpy.ops.export_scene.gltf(...)

# 修改后：try/except + fallback
try:
    import bpy
    BPY_AVAILABLE = True
except ImportError:
    BPY_AVAILABLE = False

def convert_obj_to_glb(...):
    if BPY_AVAILABLE:
        return _convert_obj_to_glb_bpy(...)
    else:
        return _convert_obj_to_glb_trimesh(...)
```

**支持的功能**:
| 功能 | Blender bpy | trimesh fallback |
|------|------------|-----------------|
| OBJ → GLB 转换 | ✅ | ✅ |
| 合并重复顶点 | ✅ | ✅ (merge_vertices) |
| SMOOTH 平滑法线 | ✅ | ✅ (fix_normals) |
| FLAT 平面法线 | ✅ | ✅ |
| AUTO_SMOOTH 按角度平滑 | ✅ | ✅ (pymeshlab) |
| 材质/纹理保留 | ✅ | ✅ (trimesh export) |

**目的**: 移除对 bpy 的硬性依赖，让 hy3dpaint 在没有 Blender 的环境下也能运行。

## 7. 已知问题与注意事项

1. **ROCm Attention 警告**: 运行时有 `Flash Efficient attention on Current AMD GPU is still experimental` 警告，属正常现象，不影响功能
2. **sdp_kernel 弃用警告**: `torch.backends.cuda.sdp_kernel()` is deprecated，是 PyTorch 版本较新导致的警告，不影响功能
3. **numba TBB 警告**: TBB 版本不匹配，并行层被禁用，不影响核心功能
4. **rembg 模型**: 首次使用会下载 `u2net.onnx`（~176MB），需网络连接。如果网络不通，可手动下载放到 `~/.u2net/` 目录
5. **bpy / Blender**: 当前环境不可用，`convert_obj_to_glb` 已使用 trimesh + pymeshlab 作为 fallback，功能等效
   - 如需使用 Blender 版本：安装 Blender 并确保 `import bpy` 可用后，会自动切换到 bpy 实现
6. **exFAT 文件系统**: 不支持符号链接，所有模型路径通过绝对路径方式访问
7. **InPaint 功能**: `InPaint Function CAN NOT BE Imported` 警告，属于可选功能缺失，不影响核心纹理生成

## 8. 快速开始脚本

```python
import sys
import os

# 环境变量（ROCm 必须）
os.environ['TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL'] = '1'
os.environ['HF_HUB_OFFLINE'] = '1'

# 路径设置
sys.path.insert(0, './hy3dshape')
sys.path.insert(0, './hy3dpaint')
MODEL_DIR = '/media/bleuesprit/DATA/下载/Hunyuan3D-2.1'

# 导入
from hy3dshape.pipelines import Hunyuan3DDiTFlowMatchingPipeline
from PIL import Image

# 加载模型
pipeline = Hunyuan3DDiTFlowMatchingPipeline.from_pretrained(
    MODEL_DIR, device='cuda', dtype='float16'
)

# 推理
img = Image.open('assets/demo.png').convert('RGBA')
mesh = pipeline(image=img, num_inference_steps=50)[0]
mesh.export('output.glb')
print('Done!')
```
